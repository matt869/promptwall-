# Benchmark methodology

How the numbers are produced, and what they are worth.

```bash
python scripts/seed_datasets.py
python bench/harness/runner.py --out bench/results/latest.json
python bench/harness/report.py bench/results/latest.json
python bench/adaptive_attacker.py --budget 12
```

Everything runs offline. A benchmark that needs an API key is a benchmark
nobody re-runs.

## Headline results

| Defence | Recall | 95% CI | FPR | Hard-neg FPR | p99 |
|---|---|---|---|---|---|
| `no_defense` | 0.000 | 0.00–0.04 | 0.000 | 0.000 | — |
| `regex_only` | 0.311 | 0.23–0.40 | 0.286 | 0.667 | 0.04 ms |
| `rebuff_like` | 0.217 | 0.15–0.30 | 0.114 | 0.267 | 0.05 ms |
| **`promptwall`** | **0.924** | **0.86–0.96** | **0.029** | **0.067** | **1.96 ms** |

And the number that matters more:

> **Under an adaptive attacker with a 12-mutation budget, roughly 55% of
> attacks eventually evade detection.**

Both numbers are true. The second is the one to plan around.

## Why accuracy is not reported

The corpus is about 70% attacks. A defence that blocks everything scores 70%
accuracy and is unusable. Accuracy on a class-imbalanced security corpus is
not a weak metric, it is an actively misleading one.

What is reported instead:

**Recall** — attacks caught. The failure this project exists to prevent.

**Hard-negative FPR, separately from overall FPR.** Benign traffic that looks
like an attack — security training questions, a bug report quoting an
injection, a request to translate one — is what decides deployability.
Averaging it with easy benign traffic hides exactly the failure that gets a
filter switched off, at which point its recall is zero.

**Recall by family.** An aggregate conceals that catching copy-pasted
jailbreaks is easy and catching indirect injection is not.

**p99 latency, not mean.** A gateway is judged on its tail.

**Wilson intervals on everything.** The corpus is small. A recall of 0.90
over 20 samples and one over 2000 are different claims, and a point estimate
invites treating them as the same.

## The corpus

150 records, generated by `scripts/seed_datasets.py`. Templated, not scraped.

**Why templated.** The repo carries no third-party dataset licensing, results
are byte-identical across machines, and the composition is explicit rather
than whatever a scrape happened to contain.

**What that costs.** Templated attacks are easier than attacks written by
someone trying to get through. **Static recall on this corpus is optimistic
and should be read as an upper bound.**

Splits: direct, indirect (poisoned tool results), encoded, tool abuse,
multi-turn, benign general, benign hard negatives.

Intermediate turns of a crescendo ladder carry `score: false`. They are
replayed so the defence can accumulate session state but are excluded from
metrics — labelling them benign would count *detecting an escalation early*
as a false positive, penalising exactly the behaviour cross-turn analysis
exists to produce.

## Baselines

**`no_defense`** — the honest floor. Every other number is only meaningful
relative to it, and it makes the corpus's class balance visible.

**`regex_only`** — a keyword blocklist, representative of what most teams
build first. Its hard-negative FPR of 0.667 is the interesting column: it
cannot distinguish discussing an attack from performing one.

**`rebuff_like`** — a local reimplementation of Rebuff's heuristic and
similarity layers. Its LLM check and canary tokens are **not simulated**, and
the report says so.

**`llama_guard`** — reports itself unavailable unless an endpoint is
configured, rather than substituting a guess. A benchmark that invents a
competitor's score is not a benchmark, and any number produced that way would
be exactly the number that flattered us.

## Ablation

Layer contribution is measured, not assumed:

```bash
python bench/harness/runner.py --defences "promptwall[l0_normalize,l2_classifier]"
```

Disabling L1 drops the same input from `challenge` (0.696) to `allow`
(0.240). Disabling L0 makes every encoded attack invisible.

## The adaptive attacker

Static recall measures performance against a fixed corpus. A real adversary
observes what was blocked and tries again.

`bench/adaptive_attacker.py` mutates the project's own seeds against its own
defence by bounded hill climbing — synonym substitution, case noise, spacing,
homoglyphs, zero-width, base64, rot13, reframing, padding, quote framing —
keeping mutations that lower the risk score. It reports *which* operator
landed the evasion, so the output is a list of things to fix.

It has already earned its place. It found that the quoted-context discount
added to reduce false positives was itself abusable: wrapping a payload in
"Translate this sentence: ..." landed 8 evasions. The retention constant was
raised in response, with the reasoning recorded in the source.

**Caveats on its numbers.** The search is stochastic, so the evasion rate
moves a few points run to run. Operator attribution credits the *last*
mutation applied, which overstates its role in a chain. And it measures
evasion of *detection* only — the tool gate is unaffected by all of it, since
no mutation changes where the text came from.

## Known weaknesses

Left in the report rather than tuned away:

| Family | Recall | Why |
|---|---|---|
| multi-turn | 0.33 | Individual turns are genuinely innocuous. The weakest area by a distance. |
| tool abuse (direct) | 0.50 | A user requesting a tool is not inherently an attack; L4 is the control, not detection. |
| sysprompt leak | 0.80 | Extraction phrasings are open-ended. |

## Reproducing

```bash
pip install -e ".[dev,train]"
python scripts/seed_datasets.py
python bench/harness/runner.py --out /tmp/mine.json
python scripts/bench_delta.py bench/results/2026-08-26/results.json /tmp/mine.json
```

`bench_delta.py` is the CI gate. Its thresholds are asymmetric on purpose:
recall may not fall beyond noise, while false positives may move a little
more, or the gate would block every legitimate tightening of a rule.

## How to read these numbers

If you are evaluating PromptWall:

1. **Ignore the static recall.** It is measured on a corpus we wrote.
2. **Look at the hard-negative FPR.** That predicts whether you will keep it
   switched on.
3. **Look at the ablations.** They show which layers earn their place.
4. **Assume detection will be evaded.** Then ask what the tool gate would
   still have prevented. That is the guarantee that does not depend on
   winning an arms race.
5. **Re-run everything on your own traffic** before trusting any of it.
